# 手册配图补全 + 平台宣传短片

- 日期：2026-11-20
- 来源：`grill-with-docs` 拷问共识（7 条核心决策）
- 关联：ADR-0064（媒体资产分层）、ADR-0062（控制台四页统一）、ADR-0055（主题统一）、
  ADR-0058（登录页固定深色豁免换肤）、CONTEXT「操作手册」「宣传短片」「本机补美」

## 1. 问题陈述

手册 `docs/user-manual.md` 已经做到按钮级文字全覆盖，但**视觉锚点严重不足**：20 章只有 12 张
配图，第 2、6.1–6.3、7、8、9、11、16、18 章**一张图都没有**，其中第 18 章「设置与技能」在
ADR-0062 那轮刚重构成 8 段页内导航，读者要在纯文字里凭想象找到「模型库分区长什么样」。
新用户读完知道功能存在，但不知道入口在哪一屏。

同时手册第 9 行声明配图「已逐张对照当前代码核对（2026-11-19）」，而 `docs/images/` 里有 4 张
是 11-03 那代（早于 11-19 的主题统一与 11-20 的 ADR-0062 四页统一），另有几张 11-16 拍的图
被 ADR-0062 改过版式——**声明与实物不符**，这份手册的可信度靠这句话撑着。

对外还缺一块能直接甩出去的物料：README 是给要看代码的人，手册是要坐下来读的人，
没有人 60 秒就能明白「这平台能把一句话变成一个能上线的应用」。仓库当前**零视频资产**。

## 2. 方案概述

一趟演示站行程产出两个交付物：**手册配图补全**（浅色，含交互态分步图）与**宣传短片素材**
（暗色录屏）。二者共用同一次登录与同一批界面，不白跑。

- **取图**：Playwright 驱动 Chrome 打演示站 `159.75.185.70:8100`（`tsadmin`），把界面推进到
  目标状态后聚焦裁剪截图，落到 `docs/images/`，浅色主题，沿用 1280×820 @2x 与
  裁剪宽 ≤1010 CSS px 的字号契约。
- **边界**：演示站只做**只读 + 可逆预览**——导航、展开已有内容、启停应用 dev 预览栈；
  禁止发布、回滚、删除、写库。
- **短片**：60–90 秒宣传向真实录屏快剪，叙事线「一句话 → 生成 → 预览 → 上线 → 分发」，
  暗色主题、中文旁白 + 整句字幕 + 轻 BGM。需要真跑一次才存在的动效走**本机补美**。
- **成片进仓** `docs/media/`，`.gitattributes` 给 `*.mp4` / `*.webm` 加 LFS 跟踪；
  截图继续走普通 git blob。README 与手册顶部嵌播。

零产品代码改动：不碰 `app/`、不碰 `frontend/src/`。交付物是文档、图片、视频与一条 LFS 配置。

## 5. 测试决策（接缝）

现有测试**没有**任何一条校验文档配图（`git grep` 过 `tests/`，只有 `test_source_ingest.py` 把
`docs/images/a.png` 当不相关夹具）。所以本轮新建一个稳定接缝，之后每次界面重构都能复跑：

**S1（新，主接缝）`tests/test_manual_assets.py`** —— 纯静态断言，不联网、不跑浏览器：

- 手册与 README 里每个 `![](...)` 的目标文件存在；
- 手册的**零配图章节白名单**收敛到 `{1, 19, 20}`，其余 17 章每章至少 1 张图
  （按 `## N.` 与 `### ` 切段统计，把「第 18 章没图」这类回归直接钉住）；
- `docs/images/` 下不被任何文档引用的 PNG 视为孤儿，白名单为空即失败；
- 每张手册配图用 Pillow 读尺寸，宽度必须是偶数且 ≤2020 px（= 1010 CSS px @2x 的字号契约）；
- 手册第 9 行的核对声明里，声明张数与实测图片引用数一致（治「声明 12 张实际 12 张但日期是
  上个月的」这类自欺）。

**S2（新）`tests/test_promo_media.py`** —— 存在性与规格断言，成片缺失时 `skip` 而非 fail
（截图阶段与成片阶段之间有验收点，不能中途把全量测试染红）：

- `docs/media/zerocode-intro.mp4` 存在且不是 LFS 指针（体积 > 1 MB）；
- 用 `ffmpeg -i` 解析（**不依赖 ffprobe**，因为只装得到 ffmpeg 单二进制）：时长在 60–90 s、
  分辨率 1920×1080、含 1 条音频流。

**S3（复用既有契约）** 取图脚本复用 `.scratch/shots-20261116/shots.py` 的
`VIEWPORT / DSF / MAX_CLIP_CSS_WIDTH / login()`，不另起一套尺寸约定。

**完成长这样**：S1 全绿且零孤儿；`docs/images/` 张数 = 手册引用数；S2 在被要求出成片后全绿；
`git lfs ls-files` 只有那一条 mp4；人不看文字、只顺着图走一遍能在 17 个章节里指认入口。

## 7. 补充说明

**硬前提：本机缺 ffmpeg 与 edge-tts。** 已实测 `ffmpeg` / `ffprobe` / `edge-tts` 三个命令
均 MISSING，`git-lfs 3.7.1`、Playwright、Pillow 可用。方案是
`pip install imageio-ffmpeg edge-tts`（`imageio-ffmpeg` 的 wheel 自带静态 ffmpeg 二进制，
从 PyPI 走即可，不需要额外翻墙下载 gyan.dev 包），代价是**没有 ffprobe**，故 S2 的规格校验
改用 `ffmpeg -i` 的 stderr 解析。这两只包装进当前 Python 环境，装完可 `pip uninstall` 干净撤回。

**登录态是同账号单会话。** 脚本用 `tsadmin` 登录会把浏览器上的同一账号顶回 `/login`，
所以取图与出片期间不要并行手动登录演示站；`shots.py` 的 `storage_state` 缓存要复用，
减少登录次数。

**演示站的主题与预览栈是共享状态。** 录深色片子要把 `tsadmin` 的外观切到暗色（这是可逆的
用户偏好），**每拍完一组浅色手册图就复位一次**，否则浅色口径会被自己拍脏；启停的应用 dev
栈在收工前按进入时的状态停下。

**BGM 素材来源未定，默认程序化生成。** 我没有可直接进仓的无版权音乐素材。默认用 ffmpeg
合成一条极轻的 ambient pad（约 -26dB，纯程序化、零版权风险）；若你自备一条，
放到 `docs/media/bgm.mp3` 我就换用你的。

**镜像 LFS 是个已知问号。** 主仓在 Gitee（LFS 有配额），GitHub 侧是每 15 分钟单向拉取的镜像，
**镜像动作是否搬运 LFS 对象尚未验证**——推之前先确认配额，推之后要实地看一眼 GitHub 上的
视频是实体还是死指针（ADR-0064 后果条已记）。

**演示站上可能拍不到的东西**：微信小程序段（第 15 章）取决于演示站有没有真实小程序构建记录；
发布进度条只有历史发布记录可看（按 D2 不允许现场发布）。缺就在 alt 与正文里写清楚，
不硬造图。
