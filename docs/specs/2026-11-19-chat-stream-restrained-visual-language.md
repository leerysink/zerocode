# 聊天流视觉语言重做：克制对话流

- 日期：2026-11-19
- 关联：ADR-0058（登录页固定暗色豁免）、ADR-0059（视觉语言十条决策）、ADR-0029（消息流唯一真源）、
  ADR-0055（全局浅/深主题）、CONTEXT「聊天流视觉语言」「聊天页侧栏」
- 基线：`feature/console-theme`（eb77ff7）合回 master 之后

## 问题陈述

聊天页是用户唯一日常停留的界面（[ChatView.vue](../../frontend/src/views/ChatView.vue) 三栏），
但它的视觉语言各自为政：

- **几何完全不一致**：13 张卡片圆角混用 4/6/8/999，内距混用 1/2/3/4/5/6/8/10/12，每张各写
  1-3 个 1px 边框。中栏字阶混用 8 档（10 / 11 / 12 / **12.5** / 13 / 14 / 15 / 30 px），
  半像素字号是明显的手写痕迹。
- **设计体系只有一半**：换肤分支已建成 73 个语义颜色变量 × 浅深两套，但**字阶 / 间距 / 圆角 /
  阴影的 token 一个都没有**，也没有 DESIGN.md。颜色有真源，几何没有，所以每新增一张卡片就再漂一次。
- **正文被过程淹没**：消息流把思考块与工具行按发生顺序平铺，一屏常见 6 条「查看思考」灰条 +
  4 行裸工具名，真正的结论只在最底下半行（[docs/images/chat.png](../images/chat.png)）。

值得解决的理由：这是用户盯得最久的页面，观感与信噪比同时受损；而缺几何层意味着这次统一完，
下次新增卡片又会漂——「设计体系」那半个目标不落地，视觉债会持续复利。

## 方案概述

先合换肤分支拿到颜色底座（冲突面只有 `LoginView.vue` 一个文件，按 ADR-0058 裁为固定暗色豁免），
再在中栏铺一层**与主题无关的几何 token**，把 13 张卡收进**一个两档外壳**，把相邻思考块与工具行
折成**过程组**（消息行的纯投影，实时与历史同一套规则），最后用截图基线 + 真实会话走查 +
源码守卫断言验收。

颜色不重做，后端不碰，协议不动。

### 接缝（测试靶心）

1. **新增的唯一接缝：`stores/processGroupModel.js` 纯函数** —— 展示记录列表 → 带过程组标记的
   展示列表。照 [promptRailModel.js](../../frontend/src/stores/promptRailModel.js) 的既有先例
   （导出常量 + 纯函数 + 独立测试文件）。**分组规则全部收在这里，组件只接线**。这是最高接缝：
   外壳样式与卡片内部怎么改，分组测试都不用动。
2. **复用既有接缝：`ChatCardShell` 组件契约**（variant / 标题 / 图标 / 状态 / 可折叠）——
   13 张卡的测试从「各自内部类名与样式」上移到「外壳契约 + 各卡内容槽」，几何由外壳一处钉。
3. **复用既有接缝：源码守卫测试** —— 仓库**没有 eslint / stylelint / prettier**
   （[package.json](../../frontend/package.json) scripts 只有 dev/build/preview/test），
   所以几何 token 断言写成 vitest 里读 `.vue` 文本的守卫，判定域收窄到 `<style>` 块。
4. **刻意不动的接缝**：`messageModel.normalizeMessages`（427 行测试保持绿，「实时与历史逐字
   相同的对象形状」不变式不破）、WS 协议与帧类型、后端全部。分组是**视图投影**，不是归一化，
   所以不塞进 normalizeMessages。

## 用户故事

### A. 合并前置与登录页豁免

- **US-01 换肤合并**：`feature/console-theme` 合回 master。master 已前进一个提交（登录页剧场
  4732691），不可 ff-only；双方共同改过的文件只有 `LoginView.vue`。**合并前不得改动主工作区
  未跟踪的 `docs/adr/0055`**——它与分支已提交版字节一致，改了会让合并被未跟踪文件挡住。
- **US-02 登录页固定暗色**：浅色偏好下登录页仍呈暗色剧场，不消费全局主题变量；登录成功进入
  控制台后立即按全局偏好渲染，不得把暗色带进后续页面。登录页不设主题开关。
- **US-03 副标题色值回退**：合并会把分支的 `.login-subtitle { color: var(--zc-text-faint) }`
  带进新登录页（该选择器仍存在，[LoginView.vue:607](../../frontend/src/views/LoginView.vue#L607)
  现值 `#8ba1b9`）。必须改回登录页局部暗色值——该变量在浅色下是深色文字，落到固定深底上不可见。
- **US-04 0055 正文修订**：合并完成后，把 ADR-0055 决策第 1 条范围改为「除登录页外的全部控制台
  页面」，并补 0058 关联。其余条款不动。

### B. 几何 token 与设计契约

- **US-05 几何 token 层**：[theme.less](../../frontend/src/styles/theme.less) 新增字阶 / 间距 /
  圆角 / 阴影四类变量，落在**不随 `data-theme` 换值**的位置（浅深共用）。初值：字阶 4 档
  12 / 13 / 15 / 20，间距走 4 的倍数，圆角外 8 内 6，阴影只留一层极淡投影。
- **US-06 中栏字阶收敛**：现有 8 档全部映射到 4 档，`12.5px` 半像素消灭。`30px` 孤例需看实际
  用途单独裁定归属（若属空态或大标题，归 20 档或另立一个展示档，不硬塞）。
- **US-07 DESIGN.md**：项目根新建，承载 token 表（73 个颜色变量的语义分组 + 几何四类）、
  Do/Don't、卡片两档规则、过程组口径。它是**可校验的契约**，不是说明书——每条都要能被断言或走查判定。
- **US-08 两翼节奏对齐**：`SideBar` / `FilePanel` 只把字阶 / 间距 / 圆角 / 边框替换为几何 token，
  **不改结构、不改信息密度**。

### C. 过程组投影

- **US-09 分组规则**：相邻的思考块与工具行归为一个过程组；遇到 assistant 正文、user 消息、
  notice、交互卡即断开。分组是消息记录的纯函数，实时与历史**共用同一套规则**，不引入实时独有状态。
- **US-10 摘要文案**：折叠态显示「思考 · N 个工具」，N 由组内工具行数出。**不显示耗时 / 秒数**。
  组内无思考块时只给工具计数；无工具时只给「思考」。
- **US-11 展开看原样**：展开后逐条呈现原有的 ThinkingBlock 与工具行 / 卡片，内容与折叠前逐字
  一致，不重排、不删减。
- **US-12 运行中最后一组展开**：沿用 [ThinkingBlock.vue:9](../../frontend/src/components/ThinkingBlock.vue#L9)
  的 `open = ref(props.streaming)` 判据——正在跑的组展开、工具逐条可见；历史组折叠。
- **US-13 折叠时机不得用 `message_done`**：它的语义是「本轮输出收口」，一次执行发多次；
  执行终态只由 `status` 判定（ADR-0029 后果第 1 条）。折叠判据必须与这条一致。
- **US-14 交互卡不被折进过程组**：提问卡 / 确认卡 / 委派卡是待答态载体，必须始终可见可交互，
  不得被折叠隐藏——否则用户漏答，且待答补发无处附着。
- **US-15 历史同构**：同一次执行，实时流与刷新后历史渲染出的**消息序列**同构（ADR-0029 不变式）。
  折叠态允许按 `streaming` 不同，这是既有先例，不算违反。
- **US-16 自动滚底适配**：运行中展开组高度持续变化，贴底阈值判定与滚底行为不得因此抖动或丢失贴底。
- **US-17 提问导航条不受影响**：分组后导航条的提问定位与高亮仍正确；`promptRailModel` 对
  「缺量测」的提问本来就不画横杠，分批渲染天然兼容。

### D. 卡片统一外壳

- **US-18 ChatCardShell**：新增外壳组件，契约 = variant（`interactive` / `readonly`）+ 标题 +
  图标 + 状态 + 可折叠。圆角 / 内距 / 边框 / 状态色一处定义，消费几何 token 与颜色变量。
- **US-19 交互卡档**：提问卡 / 确认卡 / 委派卡走 `interactive`，保留可辨边框与状态底色；
  待答 / 已答 / 已中断三态在浅深两主题下都可辨。
- **US-20 只读卡档**：预览卡 / 走查卡 / 巡检卡 / 抓取卡 / 下载卡 / 通用工具块走 `readonly`，
  一根细线、无底色。
- **US-21 13 张卡迁移**：全部改为消费外壳，各自 scoped CSS 里的外壳样式（圆角 / 内距 / 边框）
  删除，只留内容特有样式。最重的三张是 BrowserFlowCard（690 行 / 25 处色值）、
  PageInspectCard（357 / 18）、WebFetchCard（264 / 11）。
- **US-22 组内元素同样对齐**：DiffBlock 与 ThinkingBlock 消费几何 token；DiffBlock 的增删底色
  继续走既有 `--zc-diff-add-bg` / `--zc-diff-del-bg`，不另造。
- **US-23 新增卡片必须走外壳**：DESIGN.md 写明，守卫断言钉住「中栏卡片组件不得自写外壳圆角 / 边框」。

### E. 中栏其余部件

- **US-24 输入框与操作条**：`ChatInput` / `ChatAppActions` 按几何 token 对齐字阶 / 间距 / 圆角；
  附件缩略图、模型下拉、压缩 / 发送 / 停止按钮在浅深两主题下可读。
- **US-25 TodoBar 与导航条**：对齐几何节奏；导航条的固定居中盒几何（200px 盒高）不变。
- **US-26 气泡形态**：user 气泡与 assistant 正文按克制流重定底色与宽度口径；assistant 正文
  保持 100% 宽，不推翻既有的思考块宽度裁定。

### F. 验收

- **US-27 改前基线**：合并后、动视觉前，用外置 Chrome 抓一套基线截图（聊天顶部 / 长流中段 /
  提问卡待答 / 确认卡 / 走查卡 / diff / 深色同角度）。
- **US-28 改后对比**：同角度重抓逐张对照。浅色不得出现对比度倒退，深色可读性不得倒退。
- **US-29 真实长会话走查**：造一个含多轮工具调用、提问、确认、委派、预览、走查的真实会话，
  走查运行中 → 收口 → 刷新 → 切会话 → 切回全过程。
- **US-30 几何守卫断言**：vitest 源码扫描，中栏组件 `<style>` 段不得出现裸 px 字号与圆角。
  判定域收窄到 style 块，排除模板与注释里的合法 px（width / height / max-width 不在管辖内）。
- **US-31 既有测试全绿**：聊天簇 vitest 定向全绿；全量 vitest 用 `--maxWorkers=4`。

## 已定决策

来自拷问共识，避免后续翻案（完整取舍见 ADR-0059）：

1. 主目标＝视觉美观与设计体系，**不是**降噪 / 性能 / 功能补齐。
2. 基线＝先合 `feature/console-theme`，站在 73 个语义颜色变量上做，不重做颜色。
3. 登录页固定暗色豁免，不跟随主题（ADR-0058）。
4. 视觉标尺＝Claude / ChatGPT 式克制对话流。
5. 力度＝前端投影聚合，**不动后端**；耗时 / 时间戳刻意不做。
6. 卡片＝抽 `ChatCardShell` + 两档变体，不是只收变量、也不是单一弱线形态。
7. 范围＝中栏全量，两翼只对齐几何节奏。
8. 体系＝DESIGN.md + 新增几何 token 层，几何与主题无关。
9. 运行中最后一组展开、历史组折叠，沿用 `streaming` 判据。
10. 验收＝截图基线 + 真实会话走查 + 几何守卫断言，不做自动像素 diff。

两条关键澄清：

- **ADR-0029 的同构不变式不禁止分组投影**。它约束的是消息序列，不是平铺形态，也不约束折叠态。
  拷问初期误判为「触碰 0029」，已纠正。
- **耗时不做的根因是不可重建**，不是嫌麻烦：`created_at` 在
  [messageModel.js:51](../../frontend/src/stores/messageModel.js#L51) 被刻意丢弃，实时与历史
  都重建不出耗时，而 ADR-0029 规定不可重建字段不得参与已答态渲染。将来若要秒数，必须先改
  存储与投影。

## 测试决策

- **主靶心 `processGroupModel.test.js`（新）**：分组边界（遇正文 / user / notice / 交互卡断开）、
  工具计数、实时与历史同规则、交互卡不入组、空组与单元素组、最后一组展开判据。夹具**必须来自
  真实后端产出的消息行**，不手写「我以为历史长这样」；场景要覆盖挂起等人时刷新，不能只覆盖跑完之后。
- **`ChatMessages.test.js`（938 行）重钉**：卡片路由与去重闸口径不变，渲染结构从平铺改为分组；
  历史同形断言改为「序列同构 + 折叠态按 streaming」。这是本次最大的测试牵动面。
- **13 张卡测试上移**：各卡只断言内容槽与三态文案，外壳几何由 `ChatCardShell.test.js` 一处钉。
  `AskUserCard.antd.test.js` 真挂 antd 的 radio value 回归必须保留。
- **`messageModel.test.js`（427 行）不动**：形状不变式保持，分组不塞进归一化。
- **`markdownview.test.js` 的「markdown-it 只构造一次」断言不动**：单例位置不改。
- **守卫断言要用变异测试钉住接线**：纯函数有测试 ≠ 被调用；同一字面量出现 N 次会假绿。
  故意在中栏塞一个裸 px 字号，守卫必须变红。
- **happy-dom 不规范化 CSS**：颜色与几何断言按类名 / 属性 / 源码文本口径，**不算计算样式**。
- **后端零改动** → `tests/test_ws.py` 的帧数硬断言不动。

## 明确不做

- 耗时 / 时间戳 / token 用量（要动存储与投影，ADR-0059 决策 5）。
- 后端与 WS 协议的任何改动。
- 虚拟滚动、服务端分页、接口瘦身（2026-11-09 延迟 spec 已否，本次不翻案）。
- 左右两翼的结构重构（只对齐几何节奏）。
- 复制消息 / 代码块复制、手动滚到底按钮、会话内搜索、消息编辑分叉（属「功能补齐」义项，另开）。
- 窄屏 / 移动端响应式（聊天簇 `@media` 仍为零，属另一义项，另开）。
- 登录页亮色剧场（ADR-0058 已否）。
- 过程降噪之外的任何新交互。
