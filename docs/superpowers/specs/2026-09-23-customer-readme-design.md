# 客户版 README 重设计 — 设计规格

日期：2026-09-23　状态：已与用户对齐（方案 A：价值叙事型）

## 1. 背景与目标

现 README.md 是开发者施工手册（启动步骤、接口一览、环境变量、分支约定），不适合客户首读。
目标读者为**潜在客户/决策者**，场景为**售前展示**：打开仓库 10 秒内被抓眼球，2 分钟明白
平台价值，5 分钟知道怎么开始。要求中英混排（标题与 tagline 附英文，正文中文）。

## 2. 内容口径（用户已确认）

- 读者与定位：售前展示为主；技术细节从 README 主体收敛。
- 结构：价值叙事型 + 末尾「能力速查」小表（吸收功能矩阵方案的一个元素）。
- 「会带来什么影响」：收益 + 边界并存；边界口径为**支持 Windows/Mac/Linux + Docker 环境、
  支持局域网/域名远端访问**；最适合台账/登记/查询/审批类中小应用；超大型核心系统仍需专业开发。
- 预览图：功能章节用**实拍真实界面**；仅 Hero 一张用 AI 生成概念图（用户已点头此替换点）。
- 语气红线：只写已交付能力，不出现施工状态词（M1/M2/在途/未开始）；不吹牛
  （禁「颠覆」「零基础变程序员」类话术）；术语与 CONTEXT.md 一致（平台网关、应用域名、控制台）。
