# zerocode 部署发布套件（v2）— 08 平台 UI 与应用管理

- 日期：2026-09-18
- 关联：全部文档（本档是各能力在界面上的汇合点）、v1 设计 §6（既有三栏布局与配置页）

## 1. 需求背景

零经验用户的全部操作都发生在 zerocode 界面里：新建应用（向导）、聊天生成（v1 既有）、预览（03）、发布与 URL（04/05）、迁移记录（07）、环境体检（D9）。本档定义 UI 信息架构、页面行为与状态呈现，风格沿用平台约定：素雅低饱和、middle 尺寸、中文界面、表格 columns+bodyCell、弹窗表单 label 120px 右对齐、抽屉 ≥60%（重内容 80%）。

## 2. 用户故事

- S-08-1 王厂长打开 zerocode，左侧导航多了一个「应用」入口，进去就是应用卡片列表，每个卡片一眼看清"跑没跑、网址是多少、怎么操作"。
- S-08-2 新建应用三步向导：起名字 → 选规模 → 确认，30 秒建完直接进聊天页开始说需求。
- S-08-3 他从不打开 Docker 命令行：Docker 没启动时所有按钮变成"启动 Docker"引导，一切可自助。

## 4. 详细设计

### 4.1 信息架构

```
侧栏：工作区与聊天（v1） ｜ 应用（v2 新增） ｜ 设置（v1 + 部署环境卡片）
应用页：卡片网格列表
  卡片：名称 · [小型·Vue3+FastAPI] · dev●running prod●running
        URL 行（prod 局域网地址，复制图标）
        按钮：聊天 ｜ 预览 ｜ 发布/停止 ｜ 详情 ｜ 更多（启动/重启/回滚/删除）
  空态：「还没有应用 → 新建应用」向导引导
聊天页（应用上下文）：v1 三栏不变；右栏 +预览页签；输入区 +应用徽标
```

### 4.2 关键组件

| 组件 | 位置 | 要点 |
|---|---|---|
| `AppsView.vue` | views | 卡片列表 + 向导入口；轮询退化为 WS 事件驱动（FR8-10） |
| `AppWizardModal.vue` | views | 三步 Steps；slug 实时校验（debounce 调 `POST /apps/validate-slug`）；完成页结果摘要 |
| `PreviewTab.vue` | 聊天右栏 | iframe + 工具栏 + 空态/失败态（03 §4.4） |
| `PublishProgressModal.vue` | views | 分步清单（04 §4.1 七步）+ 日志尾随区 + URL 完成态 |
| `AppDetailDrawer.vue` | views | 80% 抽屉，五 Tab：概览/数据库/SQL 变更/发布历史/日志 |
| `EnvHealthCard.vue` | 设置页 | 五项体检 + 修复动作；顶栏提醒复用其状态 store |

### 4.3 状态呈现规约（全 UI 统一）

| 状态 | 颜色/图标 | 文案 |
|---|---|---|
| running | 绿点 | 运行中（附 URL） |
| stopped | 灰点 | 已停止 |
| starting/publishing | 蓝点旋转 | 启动中… / 发布中… |
| unhealthy | 橙点 | 体检未通过 |
| error | 红点 | 出错了（点击看原因） |
| warning（再扫描） | 黄标 | 需要修复（点击看详情） |

### 4.4 REST/WS 汇总（引用各档，本档不重复定义）

应用 CRUD（01）、dev 生命周期（03）、prod 与发布（04）、URL/网卡（05）、迁移（07）、配置键（v1 `PUT /config` 扩 `deploy.*` 白名单）。WS `/ws/deploy/{app_id}` 事件全集：`dev_status / dev_log / migrate_result / publish_step / build_log / prod_status / publish_done`。

## 5. 错误处理（UI 侧统一原则）

1. 任何 4xx/5xx 一律翻译成"人话 + 下一步动作"，原始报错折叠在"技术详情"内。
2. WS 断线：列表卡片状态转灰并标"连接中断"，恢复后自动全量刷新。
3. 长任务（发布）页面切换不中断：进度在应用页顶部横幅续显。
4. 并发防护：publishing 中禁用发布/回滚/删除按钮；dev starting 中禁用重复启动。

## 6. 验收标准

1. 全新用户从安装到首个应用发布完成，全程只使用界面操作（零命令行）可达成（对照 00 §10 验收 1）。
2. Docker Desktop 未启动：应用页所有动作按钮 → 体检卡片红色项 + 一键启动按钮，点击后 Docker 就绪即可继续原操作。
3. 向导三步创建 small/vue3-fastapi 应用 → 自动跳转聊天页且应用徽标正确显示。
4. 发布弹层七步状态与 WS 事件一致，失败态可见"发给 AI 修复"且消息预填正确。
5. 删除应用双确认文案与输入 slug 交互符合 FR8-08；回滚警示文案与 04 §4.4 一致。
6. 配置页修改端口段后新建应用按新段分配。
