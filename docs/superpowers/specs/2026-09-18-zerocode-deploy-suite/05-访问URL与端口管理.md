# zerocode 部署发布套件（v2）— 05 访问 URL 与端口管理

- 日期：2026-09-18
- 关联：00 总览（D1/D5）、01 应用模型、03 Dev 预览、04 Prod 发布

## 1. 需求背景

D1/D5 已定：局域网场景、每应用独立端口、仅前端端口对外。本档定义端口如何分配、URL 如何生成展示、局域网同事如何被引导访问（防火墙/网卡 IP 两个非技术用户必踩的坑）。

## 3. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR5-01 | 端口分配器：范围 `[deploy.port_base, deploy.port_max]`（默认 8210-8399），按应用成对分配——prod=偶、dev=奇（8210/8211、8212/8213…）；分配结果持久化于 app_project 并同步 app.json | P0 |
| FR5-02 | 冲突规避：分配前探测宿主端口占用（被其他程序占用则跳到下一对）；运行中应用端口被外部抢占时，状态机标 error 并提示 | P0 |
| FR5-03 | URL 生成：`http://<host>:<port>`；应用页同时给出 `localhost` 形态（本机）与局域网 IP 形态（发同事）；局域网 IP 通过枚举本机网卡 IPv4 获得，多网卡时列出候选并允许用户指定默认网卡（记住选择） | P0 |
| FR5-04 | 一键复制：复制纯文本 URL；发布完成弹层带大号地址与复制按钮 | P0 |
| FR5-05 | 局域网访问排查指引：内置帮助卡片（Windows 防火墙放行端口的具体图文步骤、检查是否同网段、ping 测试说明） | P1 |
| FR5-06 | 应用前端端口绑定 0.0.0.0（compose `ports: "<port>:5173/80"`），使局域网可访问；平台自身 8100 维持 127.0.0.1 不变 | P0 |
| FR5-07 | 端口耗尽（>95 对）或范围非法：创建应用时报错并提示调整 `deploy.port_base/port_max` | P1 |

## 4. 详细设计

### 4.1 端口分配器算法

```
allocate_pair():
  used  = {已登记 app_project 的 prod/dev 端口}
  probe = 从 port_base 起按偶数步进：
            prod = p, dev = p+1
            若 p 或 p+1 越界 / 在 used / 被 TCP 探测占用 → 下一对
  返回首对可用；写入 app_project + app.json（事务顺序：先 DB 后文件，失败回滚）
```

- 端口占用探测：socket connect 127.0.0.1:<p> 快速失败即视为可用（listen 探测），超时 200ms。
- 已有应用端口**永不复用**给新应用，即使该应用已删除——不，删除应用即释放其端口（01 FR1-07），可复用；仅"运行中/存在记录"的应用端口受保护。
- 配置键（app_config，08 配置页可改）：`deploy.port_base=8210`、`deploy.port_max=8399`、`deploy.keep_versions=5`、`deploy.health_timeout=60`、`deploy.auto_stop_dev_on_exit=true`、`deploy.default_nic`（用户选定的网卡 IP，空=自动）。

### 4.2 URL 展示规则

| 场景 | 展示 |
|---|---|
| 应用详情/列表 | dev：`http://localhost:<dev_port>`（仅本机预览用）；prod：本机 `http://localhost:<prod_port>` + 局域网 `http://<nic_ip>:<prod_port>`（可复制） |
| 发布完成弹层 | 大号局域网 URL + 复制按钮 + "打不开？查看排查指引" |
| README（01 §4.1） | 发布成功时平台把当前局域网 URL 写入应用 README 顶部（每次发布刷新） |

- nic_ip 候选：`socket.getaddrinfo(socket.gethostname())` + 连接对端 UDP 8.8.8.8 取主出口 IP（不发包）双途径取并集，过滤 169.254.*/127.*/容器网段（172.17-31 保留段标注"可能是 Docker 网卡"）。
- 多候选时 UI 下拉选择，选择持久化 `deploy.default_nic`，URL 生成即用。

### 4.3 防火墙与局域网引导（FR5-05）

- 首次发布成功后弹层附"局域网访问"提示卡：Windows 首次放行时系统会弹防火墙询问，勾选"专用网络"；若已错过弹窗，给出 PowerShell 单命令（复制即用）：`netsh advfirewall firewall add rule name="zerocode-app-<slug>" dir=in action=allow protocol=TCP localport=<port>`（标注：需管理员运行，用户可复制给 IT）。
- 排查三步（UI 帮助卡固定内容）：① 两台电脑是否同一网段（对比 IP 前三段）；② 服务机防火墙是否放行（给命令）；③ 浏览器地址是否完整含端口。
- 平台不做系统防火墙自动修改（安全边界，明示为非目标）。

### 4.4 与平台 8100 的关系

- zerocode 平台自身仍绑 `127.0.0.1:8100`（v1 约束不变，SSRF 面不扩大）；应用端口独立暴露。
- 平台 UI 内嵌 iframe 只加载 `http://localhost:<dev_port>`（本机），不涉及跨机器。

## 5. 接口

| 方法与路径 | 说明 |
|---|---|
| `GET /apps/{id}/urls` | `{localhost, lan, lanCandidates[], defaultNic}` |
| `PUT /config` 键 `deploy.default_nic` | 记住网卡选择（复用 v1 配置通道，deploy.* 键加入白名单） |
| `GET /system/nics` | 网卡 IPv4 候选列表（含 Docker 网段标注） |

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| 分配时端口全被占 | 400 "端口段已用尽，请在设置中扩大端口范围" |
| 宿主程序在应用启动后抢占端口 | compose 容器实际起不来 → 状态机 error，提示"端口 <p> 被其他程序占用，重启该应用将自动更换端口"（重启走重新分配） |
| 多网卡选错（用户选了 VM 虚拟网卡） | 排查指引首条即"换一个网卡地址试试"，UI 保留候选下拉随时切换 |
| 端口配置改为特权端口（<1024）| 400 拒绝并说明 |

## 7. 验收标准

1. 连续创建 3 个应用：端口对 8210/8211、8212/8213、8214/8215 顺序分配，无冲突。
2. 预占 8210（宿主起测试监听）后再建应用：自动跳到下一可用对。
3. 发布完成后应用页与弹层 URL 正确；多网卡机器上可切换候选并记住。
4. 同局域网第二台机器按 URL 可访问 prod 应用；未放行防火墙时按指引可自助解决。
5. 删除应用后其端口对可被新应用复用。
