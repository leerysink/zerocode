# zerocode 部署发布套件（v2）— 02 技术栈模板与生成规范

- 日期：2026-09-18
- 关联：00 总览（决策 D3/D4/D10）、01 应用模型、03 Dev 预览、04 Prod 发布

## 1. 需求背景

"毫无开发经验的人生成可用程序"的关键不是让 AI 自由发挥，而是**把技术选型锁死在平台掌握的模板内**：脚手架铺底（D10）+ AI 增量开发。本规范定义四种栈的模板内容、版本锁定、生成契约，让"AI 生成质量"从玄学变成工程。

| 规模 | 栈标识 | 组成 | 适用 |
|---|---|---|---|
| small | `vue3-fastapi`（主推） | Vue3 + FastAPI + SQLAlchemy2 + asyncpg | 表单/台账/查询类管理应用 |
| small | `vue3-node` | Vue3 + Express4 + pg | 前后端同语言偏好 |
| small | `static` | Vue3 纯前端 | 个人小工具，无后端无库 |
| large | `vue3-springboot`（锁定） | Vue3 + Spring Boot 3 单模块 + MyBatis-Plus | 多角色/流程类业务系统 |

数据库一律 PostgreSQL（D2/D7）。前端一律 Vue3 + ant-design-vue，风格沿用平台约定：素雅低饱和、控件 middle、中文界面、表格 columns+bodyCell 模式。

## 2. 用户故事

## 4. 详细设计

### 4.1 模板目录（平台仓内，随平台发布）

```
app/templates/
├── vue3-fastapi/    # frontend/ + backend/ + sqlchange/ + deploy(Dockerfile×2) + README 模板
├── vue3-node/
├── static/
└── vue3-springboot/
```

铺底时占位替换：`{{SLUG}}`、`{{APP_NAME}}`、`{{DEV_PORT}}`、`{{PROD_PORT}}`、`{{DEV_DB}}`、`{{PROD_DB}}`。compose 文件不进模板——由 DeployEngine 按栈渲染（03/04），保证平台升级编排逻辑时旧应用也能受益。

### 4.2 各栈骨架要点

**vue3-fastapi（M1 首发栈）**
- backend：FastAPI + SQLAlchemy 2（asyncpg）+ pydantic-settings；`app/main.py` 挂 `/api` 路由与 `/api/health`；`DATABASE_URL` 从环境变量读；`uvicorn app.main:app --host 0.0.0.0 --port $APP_PORT`；requirements.txt 锁定 fastapi/uvicorn/sqlalchemy/asyncpg/pydantic-settings。
- frontend：Vite5 + Vue3 + ant-design-vue（按需引入）+ pinia + axios；`vite.config.js` dev 代理 `/api → http://backend:8000`（容器内服务名）；`npm run build` 产物给 nginx。

**vue3-node**
- backend：Express4 + pg8；`/api/health`；`DATABASE_URL`/`APP_PORT` 环境变量；Dockerfile `node:20-alpine`。

**static**
- 无 backend 目录；prod 仅 nginx 静态；dev 仅 vite。数据存 localStorage/导出文件（模板 README 说明边界）。

**vue3-springboot（D3 锁定形态）**
- 单模块 Maven 工程：`pom.xml`（spring-boot-starter-web/validation、mybatis-plus-spring-boot3-starter、postgresql、actuator）；JDK 17；`application.yml` 读 `SPRING_DATASOURCE_URL/USERNAME/PASSWORD` 与 `SERVER_PORT`；`/actuator/health`；包名 `com.<slug>.app`；`Dockerfile` 多阶段 maven:3.9-eclipse-temurin-17 构建。
- MyBatis-Plus 约定：表名/字段 snake_case，实体驼峰，逻辑删除字段 `deleted`，统一返回 `{code, msg, data}`。

### 4.3 版本锁定基线（模板内写死，AI 不得降级/替换）

| 栈 | 锁定项 |
|---|---|
| 通用前端 | vue ^3.4、vite ^5、ant-design-vue ^4、pinia ^2、axios ^1 |
| vue3-fastapi | python 3.12、fastapi ^0.115、sqlalchemy ^2.0、asyncpg ^0.29、uvicorn ^0.30 |
| vue3-node | node 20-alpine、express ^4.19、pg ^8.11 |
| vue3-springboot | JDK 17、spring-boot ^3.3、mybatis-plus-spring-boot3 ^3.5、maven 3.9 |

## 5. 应用契约（注入 AI system prompt 的规范文本，随栈裁剪）

```
【应用契约】当前工作区是一个 zerocode 应用工程（<名称>/<slug>）。
1) 目录：frontend/（Vue3+antdv）、backend/（<栈>）、sqlchange/、deploy/。
2) 技术栈与版本以现有脚手架为准，只能追加依赖，不得替换/降级锁定版本。
3) 一切数据库结构或数据变更必须写成 sqlchange/V<YYYYMMDD>_<两位序号>_<说明>.sql
   （写前查看目录取下一个序号；一个文件一个逻辑变更；文件头注明用途与影响表；
   禁止改写已存在的迁移文件）。代码里不得出现建表/改表语句，不得硬编码数据库连接。
4) 后端从环境变量读数据库与端口：<各栈 env 名见 4.2>；必须保持 /api 前缀与 health 接口可用。
5) 前端页面用 ant-design-vue，中文界面，表格用 columns+bodyCell 模式，弹窗表单 label 宽 120px 右对齐。
6) deploy/ 与 app.json 由平台管理，禁止读写。
7) 完成功能后告知用户：可在「预览」查看效果，可点「发布」更新正式环境。
```

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| AI 违规写 deploy//app.json | 文件工具拒绝，结果回传模型并说明边界，模型自行纠正 |
| AI 直接在代码里写 DDL | 无运行时拦截（无法静态可靠识别），靠契约 + 评审提示；模板 README 向用户说明"改数据找 AI 要 sqlchange" |
| 依赖追加导致构建失败 | dev 重启失败 → 预览页显示后端启动日志与常见原因（依赖冲突/端口占用） |
| 模板占位替换遗漏 | 创建应用后自检：渲染产物中不得残留 `{{…}}`，发现即创建失败回滚 |

## 7. 验收标准

1. 每套模板铺底后的应用**零修改可预览**：dev 栈启动后打开 dev 端口看到模板首页，health 200。
2. 按契约让 AI 新增一个"带建表的 CRUD 页面"：产出落在正确目录、SQL 进 sqlchange、预览可用、发布可过健康检查。
3. 契约注入生效验证：同会话内 AI 能正确引用 slug/端口/库名，且对 deploy/ 的写请求被拒。
4. 四套栈的 Dockerfile 在 prod 构建中均成功产出可用镜像（M3 全量验收）。
