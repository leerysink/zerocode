# 会话状态角标：5 秒轮询 + 页面级提醒

左侧会话列表此前只在挂载时拉一次，跨会话看不见「正在跑 / 在等我回答 / 已结束」。
决定新增一个按账号汇总的实时会话状态接口（运行中 / 挂起类型 / 最近结果 + 结束时间），
侧栏每 5 秒轮询一次、页面隐藏时暂停；绿/红结束提醒只在本次页面打开期间出现，
点击即消并打开该会话，刷新即忘、不落库。原因有两条：一是不为状态提示另开第二条 WS
（与 ADR-0020 同款取舍，聊天页已有一条按会话的连接）；二是页面级提醒省掉「已读」
持久化与跨设备同步的整套模型，符合这个提示只服务当下扫视的定位。

## 备选方案

- **用户级 WS 推送**：实时性最好，但要新增全局连接、订阅与断线重连模型，改动面远大于收益。
- **服务端记录已读**：绿/红可跨刷新保留，但要新增完成时间与已读标记的持久化，属另一件事。
- **只显示当前会话**：零后端改动，但切走后就看不到其他会话的状态，正好丢掉核心诉求。

## 后果

- 结束态最多晚 5 秒出现；页面打开前就已结束的执行不补提醒——否则历史里大量 idle 会话
  会被误当成「刚完成」。
- 判据用「结束时间晚于页面打开时间」而不是「轮询是否看到了 running」，短执行因此不会漏。
- 运行中/挂起状态取后端进程内存（hub），不读库里可能滞后的 `chat_session.status`，
  避免进程重启后残留幽灵转圈。
