# 0024 工作台保存：手动 Ctrl+S、保存前冲突检测、只恢复页签列表

工作台的文件保存语义固定为三条：Ctrl+S 手动保存，页签以脏标记表示未保存；保存前用打开时记录的 mtime 做冲突检测，磁盘已被他人（典型是聊天页 Agent）改动时返回冲突并由用户选择覆盖/重新加载/取消；页签列表按 workspace 持久化到 localStorage，未保存内容不持久化，刷新后一律从磁盘重读。

理由：工作区是 Agent 与用户共享的写入口，后写覆盖会静默抹掉 Agent 刚改完的代码，冲突检测是这里唯一能防住「保存吃掉别人改动」的机制。草稿不落浏览器存储同样是为了不制造陈旧副本：VSCode 的 hot exit 在有外部写者的工作区里会把「上次没保存的旧内容」变成一颗定时炸弹，刷新后重读磁盘是更诚实的状态。手动保存而非自动保存，则避免误编辑直接落盘。

被否决的方案：自动保存（误编辑即落盘，且与冲突检测语义纠缠）；页签与草稿一起恢复（hot exit 观感好，但旧草稿可能覆盖 Agent 的新改动）；不检测、后写覆盖（实现最省，风险最高）；不持久化页签（多文件编辑反复丢上下文）。

## 后果

- `/api/files/read` 需回带 mtime，`/api/files/save` 接收期望 mtime 并在不匹配时返回 409；这条契约属于保存链路，不只是前端状态。
- mtime 版本戳在 JSON 里以十进制字符串承载，而不是数字：纳秒值约 1.79e18，超过 JS Number 的 2^53，数字会在浏览器端被舍入，导致每次保存都误判冲突。
- 刷新恢复只恢复页签与当前激活项；每个恢复的页签重新走 `/files/read` 拿内容与新 mtime。
- 关闭脏页签与 beforeunload 都要拦截提醒；这是「未保存内容不持久化」的配套，否则刷新即静默丢失。
