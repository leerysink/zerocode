# 0039 应用数据轨按环境分三段：公共 / dev / prod

应用开发期往 `sqlchange/` 追加的数据脚本，此前 dev 预览与 prod 发布跑的是**同一份**——于是"为了让预览
看起来有效果"而灌的示例行，会跟着上线进生产库。我们决定把数据轨分成三段：`sqlchange/` 顶层=公共段（两库
都跑）、`sqlchange/dev/`=只进 `<slug>_dev`、`sqlchange/prod/`=只进 `<slug>_prod`；一次执行跑「公共段 +
本环境段」，内容由写脚本的一方（AI 会话）按**参考数据 vs 演示数据**口径拆成两份。存量文件一律不搬迁。

## 备选方案

- **只做两段互斥（`dev/` 与 `prod/`，没有公共段）**：一眼看出哪些脚本分环境，但基座 RBAC/菜单这类两边
  内容完全相同的种子要维护两遍，且回填刷值本就该无条件生效——被否。
- **平台提供"从 dev 库 dump 数据生成 prod 种子"的接口与页面按钮**：拷问过程中一度选中，随即被用户否决
  （"我就是想每次加功能新增 sql 脚本时，把 dev 和 prod 分开"）。需求是**写入时的分叉**，不是**存量数据的
  搬运**；做导出器会引入表勾选清单、密码哈希/业务流水随包外泄等新问题，收益不在这里。
- **发布流程自动生成 prod 文件**：等于在发布现场静默写盘，产物无人预审，与既有"已应用文件不得回改"的
  纪律冲突——被否。
- **只改目录约定、不动生成方**：那么 prod 段永远靠人记得写，漏写即线上缺数据。折中进 contract/prompts，
  让写功能的一方成对产出。

## 后果

- **记账键语义变了**：`sqlchange_history.filename` 从 basename 改为**相对 `sqlchange/` 的路径**。顶层文件
  的相对路径恰好等于裸文件名，所以存量记录与新逻辑天然兼容；反之若继续用 basename，`D…​_x.sql` 与
  `prod/D…​_x.sql` 同名时会在同一库里撞主键、误判篡改。同名的环境段文件因此是允许的（各库各记各的）。
- **迁移容器需要知道自己在哪个环境**：`run_sqlchange` 那个一直空转的 `env` 参数终于有了消费方，并经
  `ENV` 传给 sqlrunner；dev/prod 两套 compose 的 `migrate` 服务各带自己的 `ENV`。挂载点仍是整个
  `../sqlchange:/sql`，子目录跟着进去，不必多挂卷。
- **一切"看目录"的地方都要改成递归 + 相对路径**：发布前的命名闸门、待办清单接口、商店上架的锚点比对
  与打包拷贝（目标路径要先建父目录）、结构漂移校验。漏一处就是「文件在盘上但锚点说它没了」这类假故障。
- **漂移校验的 scratch 库按 dev 分支 fold**：它比对的是 `<slug>_dev` 的实际结构，若 scratch 跑成 prod 段，
  每次发布都会红在"结构与文件不一致"。
- **商店包原样带三段**：买家安装时对 dev 与 prod 两库各跑一次基线，于是买家 dev 库有和作者一样的示例数据
  （好上手），prod 库干净。代价是演示数据随包分发——按「演示数据只进 dev 段、买家 prod 不跑 dev 段」这条
  路径它进不了线上库，但不进包以外的过滤。注意锚点取的是 **prod 库**历史，`dev/x.sql` 天然不在其中，
  所以 dev 段必须在打包时另走一次目录拷贝带出去（不过 checksum 闸门）——只按锚点拷文件的旧逻辑会把整段静默丢掉。
- **成对靠约定，不靠闸门**：prod 段缺文件是合法状态（演示数据本来就不该有 prod 变体），所以发布时不做
  "两段必须成对"的硬校验；本次接受"漏写线上种子"的风险，换取不引入误报成山的成对检查。
- **锚点取数要钉 `COLLATE "C"`**：`anchor.HISTORY_SQL` 原本 `ORDER BY filename`，跟着库的 collation 走。
  平台 PG 实例是 `en_US.utf8`，默认序把 `prod/D….sql` 排在 `V….sql` 之前，而 run.sh（busybox `ls|sort`，C locale）
  先跑公共段。三段之前两种序对所有合法文件名结果相同（前缀只有大写 `V`/`D`），三段一进来就分叉了——
  表现为「追加一个顶层文件反而破坏前缀约束 L、上架被拒」的假故障。锚点顺序从此显式钉字节序，与执行顺序同源。
- **CRLF 与幂等纪律不变**：环境段文件同样是一次性、一经应用不得修改；重放安全的 `ON CONFLICT` 写法要求
  照旧（见 ADR-0014 对平台轨的同类约束，两者是不同轨，别混）。
