# 0062 控制台四页统一：薄组件边界与设置页导航形态

- 状态：Accepted
- 日期：2026-11-20
- 关联：ADR-0048（应用卡仪表带与常驻工具条）、ADR-0055（控制台主题统一）、
  ADR-0058（登录页固定深色豁免换肤）、ADR-0061（管理页运营可编辑性）、
  CONTEXT「薄组件」「运营台（store admin）」

## 背景

商店页、商店管理页、设置页是各自长出来的：只有应用页 `AppsView.vue`（1361 行）经过 ADR-0048
那轮卡片语言设计。四页并排看像四个产品——应用页是卡片流 + ☰ 菜单 + 行内三段动作，设置页是
`a-tabs` 里塞两大块长表单，管理页是自绘 tablist 加只读卡片。要把后三页拉到同一套语言，
先要决定「统一」做到哪一层：换皮、重排结构，还是抽公共组件。

## 决策

1. **只抽三个薄组件**：`ZcPageHeader`（页头 + 返回 + 统计格）、`ZcEntityCard`（卡片骨架：
   封面 / 标题 / 摘要两行截断 / 左缘状态轨 / ☰ 菜单槽 / 动作条槽）、`ZcEmptyState`。
   它们只收 props 与插槽，不含取数与业务逻辑。
2. **应用页换用薄组件，但逻辑与选择器不动**：`AppsView.test.js` 有 1420 行在盯应用页的
   卡片、菜单与动作条，它充当这次抽取的回归网——改的是模板归属，不是行为。
3. **不封 antd 基础层**：不包装 `a-card` / `a-modal` / `a-drawer` 做全局替换，业务页继续
   直接用 antd。封层会震到查询控制台、聊天卡片这些不相干页面，收益只有「少写 import」。
4. **设置页用页内左侧二级导航 + 右侧分区，不开 `/settings/*` 子路由**：分区为
   模型库 / 模型接入 / Agent 行为 / 上下文与记忆 / 联网与工具 / 环境与预览 / 外观 / 账号。
5. **返回按钮沿用 `BackButton` 固定回 `/`**，四页统一，不改走 `router.back()`。
6. **卡片网格统一三列等高，应用页跟着改**：等高与摘要两行截断内建在 `ZcEntityCard`，
   不做成 prop；`AppsView` 的 `.zc-grid` 从 `repeat(auto-fill, minmax(480px, 1fr))` 不等高
   改为与商店页（32432bc）同口径的三列等高。这是对 ADR-0048 卡面尺寸的一处改写：
   应用页卡变窄，仪表带（`.zc-band` 的 `72px minmax(0,1fr) auto`）需按新宽度重调。
7. **审批入口收口到运营台**：商店页删除创始人专属的「待审批」页签
   （原 `StoreView.vue:215`），只留「商店 / 我的申请」；批准与驳回只在运营台的审批队列发生，
   待审批数改为 NavRail「管理」入口上的红点徽标。原本同一队列在两页各存一份，
   两处状态存在完成时间差。

## 备选方案

- **不抽组件，三页各自复刻卡片语言**：零回归风险；代价是同一套 `.zc-grid` / 状态轨 /
  菜单样式在四个文件里各存一份，必然漂移——`StoreView.vue:316` 已经出现过
  「同纪律」这种靠注释维持的约定。被否。
- **设置页开子路由做宫格入口**：每分区可深链；但 `/skills` 在 5ec4baf 就是为了避开
  父路径高亮串台才从 `/settings/skills` 提出来成为一级入口，开子路由等于把同一个坑再踩一次，
  还要连带改 NavRail 高亮与返回逻辑。被否。
- **返回走 history**：从商店页点进管理页能回商店页；但刷新后无历史时按钮会静默无反应，
  要额外判空回落，而 NavRail 是常驻的——四个页面本来都能直达，「上一页」并不是用户心智里的来路。被否。
- **等高与截断做成 `ZcEntityCard` 的 prop**：应用页可保持现状不变窄，零视觉回归；
  代价是骨架件多一个形状开关，四页里两页不等高、两页等高，看久了仍是四个产品。被否。

## 后果

- 三页重写与组件抽取互相阻塞：薄组件的插槽形状要等管理页（带编辑/详情）和设置页
  （带分区）的骨架都摸清才定得稳，交付顺序上应先做组件再做页。
- 深色块继续禁止覆写几何 token（`theme.less` 的几何块归亮色独有），新页面的间距与字阶
  一律走 `--zc-space-*` / `--zc-radius-*`，不留裸 px。
