# 0011 内置文件管理器改为独立整页，从新标签页打开

内置文件管理器（`WorkspaceExplorer`）的宿主形态从**居中弹框**改为**独立路由整页** `/workspaces/:id/files`
（`WorkspaceFilesView`），两个入口点它时一律 `window.open` 开新标签；`open` prop、`a-modal` 外壳、
90% 宽与 `58vh` 定高全部删除，不留双宿主。本 ADR **取代** ADR-0010 中「弹框形态」那一条决策；
ADR-0010 的 `/fs/ls` 懒加载、左树右预览、坚持只读三项决策继续有效——其中「只读」与「右侧只预览」
已由 ADR-0022 升级为可编辑工作台，懒加载与整页宿主不变。

理由：内置文件管理器已是默认入口（ADR-0009），承担的是「在网页里看清工程结构」这件主职，而弹框把它
压成了一个依附在调用页上的临时窗口——聊天页的会话与右栏状态、应用列表的卡片展开态和滚动位置都会被打断，
地址栏里也留不下任何可复现的位置。平台早有整页先例（`/apps/:id/db` 就是菜单里一个 `<a target="_blank">`），
同一个产品里"看数据是整页、看文件是弹框"没有依据。改成整页后地址可收藏、可后退、可开多个工作区各占一个标签，
关闭浏览器标签就是关闭它，不需要我们再实现一套关闭态。

被否决的方案：保留弹框再加一条整页路由（两套宿主、两处状态重置入口，必然分叉）；在同一标签里路由跳转
（聊天页会被卸载，会话状态与滚动位置真丢，用户只是"回不来"而不是"少一个窗口"）；把入口换成原生
`<a target="_blank">`（本机直开系统资源管理器这条分支需要先问后端与访问地址，不是纯链接能表达的）。

## 后果

- 地址只有唯一真源 `utils/openFolder.js::workspaceFilesPath`，路由表里的字面量与之由 `router/index.test.js`
  一条对拍断言钉住——两处各写一份、改一处静默断链的风险被测试拦住。
- id 全链路按字符串透传，`normalizeWorkspaceId` 只认纯数字；脏 id 不进 explorer，整页直接出一条错误提示。
  这层前置拦截不替代服务端鉴权：`app/api/files.py::_root_of` 仍按 `owner_user_id` 校验，收藏地址或手改地址
  越不到别人的工作区，最坏是 404。
- 展开态的重置触发点从「弹框 open 翻转」变成「换 workspaceId」或「点刷新按钮」；组件只 watch id，
  要不要挂载、拿哪个 id 挂载是 `WorkspaceFilesView` 的职责，explorer 不再自己感知宿主。
- `window.open` 需要用户手势的 transient activation（Chrome 约 5 秒）才不被拦截；返回 `null` 时调用方
  必须给出可操作的提示，不允许静默失败。命名窗口 `zerocode-files-<id>` 让同工作区重复点击复用标签。
- 地址里的 `?name=` 只为顶栏标题省一次请求，不是权限或定位依据；页面在拿不到名字时退回 `#<id>` 显示。
- 整页高度沿用 `calc(100vh - 40px)`（壳层账户栏占 40px），与 `db-admin.less` 同一口径；explorer 自身
  `height: 100%`，左树与预览各自内部滚动，不再依赖定高数字。
