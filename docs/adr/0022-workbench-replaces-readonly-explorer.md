# 0022 内置文件管理器升级为可编辑工作台，编辑收口到整页

原 `/workspaces/:id/files` 只读文件管理器（ADR-0010/0011）升级为**工作区工作台**：左树 + 文件页签 + Monaco 编辑区 + 状态栏，可编辑保存；聊天页右栏文件面板（FilePanel）改为只读预览 + 「在编辑器中打开」。本文取代 ADR-0010 与 ADR-0011 中「坚持只读」的决策；懒加载树、整页宿主、`/fs/ls` 数据源三项继续有效。

理由：只读形态成立的前提是「编辑在右栏 textarea 里做」，而 300px 宽、无页签、无语法高亮的 textarea 无法承担平台的主要工作——用户打开工程目录就是为了改代码。把编辑留在右栏意味着工作台永远只是「看」，而它又是默认入口（ADR-0009），用户点「打开文件夹」后还得回聊天页窄栏改文件，动线是断的。收口到整页后只有一套编辑器、一条保存链路，Agent 之外的编辑行为不再分叉。

被否决的方案：保留只读 explorer、继续用右栏编辑（两套入口、两套编辑器、两套保存路径）；把工作台做成 VSCode 完整壳含活动栏（扩展无安装机制、搜索未规划，会留一排假图标）；只升级右栏（300px 放不下树+页签+编辑器）。

## 后果

- 入口文案不变（「打开工程目录」「打开文件夹」），地址不变（`/workspaces/:id/files`，ADR-0011 的地址真源与路由对拍断言继续有效）。
- FilePanel 的 textarea 编辑与 `/files/save` 调用退场，改为「在编辑器中打开」跳转工作台并带上目标文件；保存只剩工作台一条路径。
- 「只读」不再是产品约束，但服务端写保护（`app.json`、`deploy/`）与二进制/200KB 读限制照旧；受保护文件在工作台里只读展示。
- 工作台默认深色、可切浅色；控制台其余页面不变。这条主题分叉是工作台「像 VSCode」的一部分。
