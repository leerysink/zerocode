# 0065 思考块一律默认折叠，展开意图跨收口交棒

- 状态：Accepted
- 日期：2026-11-21
- 关联：ADR-0059（撤销其决策 6 与 US-12 引用的块级判据，其余条款不变）、ADR-0029（同构不变式）、
  CONTEXT「聊天流视觉语言」「思考块」

## 背景

ADR-0059 决策 6 定了「运行中最后一组展开、历史组折叠」，块级判据落在
`ThinkingBlock.vue:9` 的 `open = ref(props.streaming)`：思考正在流的时候正文自动展开、逐字刷屏，
真正的回复被顶到最下面——正是 0059 背景里要治的「正文被过程淹没」，却在过程块自己身上留下了
最大的噪声源。诉求改为：思考中默认只显「思考中…」，点开才看正文。

顺带暴露一个原有缺陷：流式思考块与固化后的历史思考块是**两个组件实例**（`message_done` 清空
`streamingThinking` 即卸载前者），展开态无处安放。默认折叠后这缺陷从隐性变显性：用户点开读正读到
一半，本轮收口，块「啪」地折叠回去。

## 决策

1. **思考块一律默认折叠**，流式与历史同判据：撤销 `open = ref(props.streaming)` 与那条在
   `streaming` 转真时强制展开的 `watch`。头部文案不变——流式「思考中…」（带呼吸动效），
   历史「查看思考」。
2. **展开态归父层所有，并在收口那一刻交棒**：`ThinkingBlock` 的 `open` 只作初值，点击后由内部
   持有并回吐 `update:open`；`chat.js` 以 `streamingThinkingOpen` 接住流式块的展开态，
   `message_done` 收口时把它作为 `reasoning_open` 盖到固化的 assistant 记录上，历史块读它当初值。
   于是「正开着的那条」收口后仍开着，新起的一轮与刷新后一律折叠。
3. **`reasoning_open` 只活在实时记录、不落库**，且「有才传」（不补 `false`）。它与
   `awaitingConfirm` 同属"事件打在消息记录上的即时标记"：历史行永远没这个键，实时若多出一个键，
   ADR-0029 的实时 ≡ 历史同构断言当场叉开。
4. **本 ADR 只动块级判据，不动 ADR-0059 的其余条款**（分组规则、卡片两档外壳、几何 token、
   摘要不给耗时）。0059 决策 6 里「运行中最后一组**展开**」是组级判据，组与块是两层：块现在
   一律折叠，组是否仍在运行中展开，由过程组落地时（`feature/chat-visual-language`）按本 ADR 的
   口径重定，不在这里替它拍。
5. **`message_done` 在这里只用于状态交棒，不用于判定执行结束**。0059 决策 6 的告诫保持有效：
   `message_done` 一次执行发多次，终态只由 `status` 判定（ADR-0029 后果第 1 条）。

## 备选方案

- **展开态留在组件内部、收口时靠 remount 前记住**：组件在 `message_done` 那一刻就卸载了，没有
  活过卸载的地方可记，等于没解决。被否。
- **给每条消息算稳定 id，维护一张展开态表**：能撑多条同时展开、跨会话记忆，但要动
  `messageModel.js:51` 刻意丢弃 `id/seq` 的口径，同构断言跟着重钉。本轮只需要一次交棒，不值。被否。
- **展开态落库或写 localStorage**：跨刷新保持展开看着更贴心，代价是动存储与投影，与 0059
  决策 5「不可重建字段不参与渲染」同类的复杂度，收益不明。被否。
- **流式期间连「思考中…」都不给，完成后才出现可点的查看思考**：最极简，但执行中失去「它在动」
  的反馈。被否。

## 后果

- 看实时思考要多点一下；换来的是一屏不再被逐字刷屏的思考正文挤掉。
- `feature/chat-visual-language`（未合回）的 `ThinkingBlock.vue` 与 US-12/US-13 的过程组判据
  与本改动同文件冲突，合并时块级判据以本 ADR 为准，组级判据跟着重定并回来补一条 ADR。
- 消息记录上又多一个「只活在实时」的 UI 键。新增此类键必须「有才传」，并配一条同构断言钉住。
- `endRunState` 的复位集合新增一项（`streamingThinkingOpen`）。抄漏的后果仍是残块：那一项漏了
  表现为收口后新起的一轮思考块直接是展开的。
