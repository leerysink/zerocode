# 0001 平台中央网关终止 TLS，应用容器不感知 HTTPS

需要给每个生成的应用配上 `{slug}.zerocode.com` 的 HTTPS 访问。我们决定新增一个平台级中央网关（OpenResty 容器）持有 `*.zerocode.com` 自签通配证书并终止 TLS，各应用的 nginx 容器继续保持纯 HTTP 的 `listen 80`，由网关按 Host 转发过去。被否决的方案：每个应用镜像各自 COPY 证书并 `listen 443`——通配证书要装 N 份、证书轮换要重建全部应用、模板与存量应用都要改。

## 后果

- 应用侧模板与存量工程零改动，HTTPS 能力升级收敛在网关一处。
- 证书有效期/轮换只影响网关；`gateway/certs/` 必须 gitignore，不入库。
- 自签证书不受浏览器信任，需在客户端手动信任本地 CA（本机先行阶段的既定代价）。
- 通配证书只匹配一级域名，因此应用标识（slug）必须保持单段、不可含点号。
- 本机先行，后续上服务器时改的是 DNS 解析与证书签发，网关形态不变。
