# 0058 登录页固定暗色，豁免全局浅/深主题

- 状态：Accepted
- 日期：2026-11-19
- 关联：ADR-0055（本 ADR 收窄其决策第 1 条的范围，其余条款不变）、CONTEXT「控制台主题」

## 背景

ADR-0055 裁定全局浅/深主题管辖整个控制台，第 1 条明确「含登录页」。同日登录页被重做为
全屏构建剧场（3D 方块塔、生成实录终端、暗色玻璃表单，commit 4732691），整套视觉建立在深底
之上：`LoginView.vue` 硬编码 `#070d18` / `#0b1626` / `#06121f` 等深色，零 `data-theme`、
零 `--zc-` 引用。结果是浅色偏好用户打开登录页仍然是暗的，与 0055 第 1 条直接冲突。

换肤分支 `feature/console-theme` 对登录页只改了一行——旧登录页的 `.login-subtitle`
从 `rgba(0, 0, 0, 0.45)` 换成 `var(--zc-text-faint)`。该选择器在新登录页仍然存在
（`LoginView.vue:607`，值已是硬编码 `#8ba1b9`），所以合并会把这一行自动带进新登录页。

## 决策

1. **登录页列为固定暗色豁免**，不跟随全局主题偏好。与换肤已有的豁免项（终端调色板、QR、
   VSCode 蓝、已双主题局部块）同类。
2. **理由**：登录页是品牌门面与一次性场景，没有长文阅读与长时间停留需求；「构建剧场」的
   氛围依赖深底，亮底重做会垮掉。
3. **ADR-0055 第 1 条范围收窄**为「除登录页外的全部控制台页面」。0055 的其余条款——统一
   管辖、默认浅色、AccountBar 手动开关、旧键一次性继承、跨标签页同步——全部不变。
4. **登录页不设主题开关**。它不挂 AccountBar，豁免后也没有切换入口；用户在登录页切不了
   主题，这是豁免的自然结果，不另设入口。
5. **豁免边界仅限登录页自身**。登录成功进入控制台后立即按全局偏好渲染，不得把登录页的
   暗色带进任何后续页面。
6. **合并时必须回退那一行**：新登录页的 `.login-subtitle` 保持登录页局部暗色值，不得消费
   `--zc-text-faint`。该变量在浅色下是深色文字，落到固定深底上会不可见。

## 备选方案

- **另做一版亮色剧场**：严格遵守 0055，但 3D 方块塔、生成实录终端、玻璃表单三套视觉都要
  重配浅色，工作量大，且亮底上剧场氛围大概率垮。被否。
- **浅色退化为简洁表单、剧场只在深色出现**：折中，但两套形态两套代码，登录体验按主题分裂，
  此后改登录页要改两处。被否。
- **先合并、豁免问题留到视觉阶段再裁**：合并即引入一个违反 Accepted ADR 的状态，且视觉阶段
  还会再碰一次登录页。被否。

## 后果

- 浅色偏好用户进登录页是暗色、登录后转浅色——一次刻意的明暗跳变，不是缺陷。
- 登录页样式不参与语义变量换肤：新增登录页样式无需考虑双主题，但也拿不到主题变量的好处，
  色值继续硬编码。
- ADR-0055 正文的第 1 条文字修订**留到换肤合并之后**执行。合并前 0055 在主工作区是未跟踪
  文件且与分支已提交版字节一致，提前改动会让合并被未跟踪文件挡住。
