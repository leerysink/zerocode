# actor 升级为登录用户，本地账号体系 + 多账号完全隔离

平台需要"应用/会话/模型/技能都归用户"。我们决定不建云端账号服务、不新建 user 表，
而是直接给现有 actor 轻身份表加认证字段（bcrypt 口令 + 会话 token），actor 即登录主体；
运行假设是"每人本地跑一个实例"，但实例内开放注册、多账号，所有业务表加 owner 维度、
查询强制按用户隔离；首个注册账号自动成为创始人并承接全部存量数据。

## 备选方案

云端账号体系（GitHub OAuth/中心认证服务）、新建 user 表并重构 market 外键、
actor 与 user 双体系并存、单账号门锁模式——均因依赖成本、改造面或语义空洞被否。

## 后果

- 应用商店已有的 applicant_id / owner_actor / created_by 外键永久绑定登录主体语义，
  未来想拆分"市场参与者"与"平台用户"身份需付 migration 代价。
- 所有现存与新增 API 必须带用户过滤，这是长期约束而非一次性工作。
- 跨机器"账号跟云走"若将来要做，是在本方案上的增量（本地表已带 owner 维度），不冲突。
