# 小程序构建走平台侧叠加与副本补丁

小程序构建需要的 mp-weixin 依赖、脚本、manifest 段与 `project.config.json` 不写进应用源码，也不要求存量应用回填：builder 复制 `frontend/mobile` 到临时目录后，叠加平台维护的构建配置，并在副本里把 `utils/request.js` 的接口基址改为构建期注入的绝对地址，再编译上传。应用源码逐字节不动，appid 也不落源码。

## 备选方案

- **配置写进应用模板并回填存量应用**：新建应用自解释，但存量移动栈应用要逐个改 `package.json` 与 `manifest.json`，模板升级还会漂移。
- **只支持新建应用**：存量应用要发小程序只能重建，与「已有应用也要能发」冲突。
- **打包产物字符串替换**：在编译后的 JS 里把 `/api` 换成绝对域名。实现快但脆弱，容易误伤其他字符串。
- **要求用户手改 request.js**：把平台该做的事推给用户，每个存量应用都要改且无法回归验证。

## 后果

- 构建期补丁必须**严格识别预期结构**：`request.js` 的形态对不上就构建失败并给出明确提示，不静默改错。
- 叠加层要跟随 uni-app 版本与移动模板演进；`@dcloudio/uni-mp-weixin` 等依赖由平台维护，不在应用锁文件里。
- 构建与上传放在**独立小程序 builder 容器**（Node + uni-app + miniprogram-ci），不与 android-builder 或后端镜像混装；任务串行，状态落独立表，失败不影响平台与发布。
- 构建镜像需要 npm 换源与出网能力，沿用既有依赖镜像源通路；首次构建耗时与镜像体积需实测。
