# 0056 run_python：隔离 Python 沙箱，红线改写为「preset + 沙箱」

- 状态：Accepted
- 日期：2026-11-19
- 关联：ADR-0046（红线「无通用命令执行面，只允许 preset」，本票修订）、ADR-0031/0037（browser
  sidecar 隔离范式）、ADR-0053（web SSRF 判定）、ADR-0052（子 run 只读白名单）、ADR-0027（db 工具
  受控通道）、CONTEXT「Python 沙箱」「预设自检」

## 背景

Agent 能写脚本却跑不了：数据处理、算法验证、临时计算这类活，现状只能靠 `db_query` + 目测，或写个
.py 文件干看着。但 ADR-0046 把红线钉成「工具面无通用命令执行能力，只允许平台写死的 preset」，
`run_shell` 被明确否决——shell 可以 `cat deploy/.env`（绕过 M-3 凭据读禁）、`rm -rf`（绕过写保护与
确认卡）、`curl` 外发用户代码。Python 图灵完备，逐字适用同一理由。需要一种既给执行能力、又不作废
围栏的形态。

## 决策

1. **新工具 `run_python`，隔离沙箱跑模型给的任意 Python 脚本**。红线由此改写为
   **「工具面无通用命令执行能力；只允许平台写死的 preset 与隔离 Python 沙箱」**，同步修订
   `tests/test_preview_tools.py::test_no_command_execution_tool_exists`。沙箱不是通用 shell：
   它的触达面被下列围栏锁死，红线保护的是「围栏不可绕过」，而非「禁止执行」本身。
2. **工作区只读挂载 + 独立 scratch 输出区**：`deploy/` 凭据目录排除（保 M-3 读禁）；脚本读项目
   文件、写只进 scratch，**不直接写工作区**——产出由模型经 `write_file` 落盘，确认/留痕/回滚围栏
   原样成立。这是「给执行能力」与「保写围栏」的折中：拷问中先选「挂工作区读写」，因须重造写围栏
   而退回本档。
3. **不给应用库凭据**（`db_query`/`db_write` 已是受控通道，给裸凭据会绕过 dev-only + 确认围栏）；
   无 docker.sock、无平台库凭据、非 root、限资源（同 browser sidecar 范式，ADR-0031/0037）。
4. **网络仅公网**，复用 `web_fetch` 同一条 SSRF 判定（私网/本机/容器别名拒绝，ADR-0053），不另立名单。
5. **载体是一次性容器**（`docker run --rm`，与 `run_check`/`sqlrun` 同构），跑完即销毁、无状态残留。
6. **确认沿 `CONFIRM_WRITE` 档**（受 `agent.write_confirm` 控制，与 `write_file` 一致，零新增配置）；
   挂载范围 `SCOPE_ALWAYS`（不依赖应用身份，与 fs/web 同列）；**不收录 `SUBRUN_TOOL_NAMES`**
   （沙箱属执行能力，不属 ADR-0052 只读语义）。

## 备选方案

- **通用 shell / 后端进程内任意执行**：作废 M-3/写保护/确认卡/回滚全部围栏，ADR-0046 已否。被否。
- **扩 `run_check` preset**（如 backend_pytest/python_lint）：零红线改动、成本最低，但只能跑平台
  写死的检查项，补不了「临时数据处理/计算」缺口。被否（用户要的是跑任意脚本）。
- **挂工作区读写**：能力最强，但重新打开写绕过面，须重造写确认/留痕/回滚围栏，红线修订最大。
  拷问中先选后退，取只读 + 输出区。
- **沙箱断网**：最安全、封死渗出，但脚本不能抓公网数据。取仅公网复用守卫（用户拍板）。
- **恒确认 / 免确认**：前者迭代跑脚本打断多，后者任意代码 + 公网渗出无用户闸。取 `CONFIRM_WRITE`。
- **常驻 sandbox sidecar**：省冷启动，但需生命周期管理且多次执行有状态残留风险。取一次性容器。

## 后果

- **红线测试语义扩容**：从「preset 白名单 + 未知检查项拒绝」扩为「preset 白名单 + 隔离沙箱」，
  新增工具仍须同步该测试与注册表，防漂移强度不低于从前。
- **渗出面是明确接受的取舍**：只读挂载 + 公网出网意味着项目源码可被脚本外发；但 `deploy/` 凭据、
  应用库凭据、平台库、docker.sock 均不可触达，写工作区仍走 `write_file` 围栏。
- **scratch 产物在工作区外**：`read_file`（工作区相对）读不到，工具须回产物内容/清单，供模型经
  `write_file` 落盘——输入输出契约在 spec 细化。
- **冷启动与资源**：一次性容器每次冷启动（Python 远快于 mvn）；资源/超时上限、Python 版本与依赖
  策略（预装 vs 允许 pip install）由 spec 定默认值。
