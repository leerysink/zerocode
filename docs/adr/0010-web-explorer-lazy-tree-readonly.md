# 0010 内置文件管理器采用 /fs/ls 懒加载左树，坚持只读

内置文件管理器（`WorkspaceExplorer`）从“单层列表 + 双击进入 + 上级按钮”重做为**左树右预览**：目录树按 `/fs/ls` **懒加载**（展开一层才拉一层），右侧只预览文件，弹框宽 90%、树区与预览区各自定高内部滚动，打开时自动加载并展开根层。它继续**只读**——看目录与下载在此，编辑仍走聊天页右栏的文件面板。

理由：既然默认入口换成了这个弹框，它就要承担“在网页里看清工程结构”的主职，单层翻页在大工程里太吃力。选懒加载而非现成的 `/fs/tree` 全树，是因为全树体积随工程规模不可控（即便已屏蔽 node_modules/dist/backend/target 等），且 `/fs/tree` 不返回 size 与 mtime；`/fs/ls` 天然带这两项，且按需付费。坚持只读是为了不重复实现一遍右栏已有的编辑/保存/脏数据刷新链路，权限面与改造前保持一致（`app.json`、`deploy/` 的写保护本就由后端兜底）。

被否决的方案：`/fs/tree` 一次拉全树（前端最简，但看不到元信息、大工程首屏过重）；给 `/fs/tree` 补 size/mtime（改动越界到接口层，每层多一次 stat）；树与单层列表双视图切换（养两套导航状态，99% 场景只用其一）。

## 后果

- 树的可见性由 `/fs/ls` 与 `/fs/tree` 共用的 `_is_ignored_dir` 决定，屏蔽名单变动会同时影响两处口径（见 `app/api/files.py` 那段注释）。
- 懒加载必须自己处理展开态：切换工作区、关闭重开都要重置，否则新工作区接着显示旧目录。
- 目录只展开不进右栏，“当前在哪一层”完全靠面包屑表达，面包屑必须保留。
