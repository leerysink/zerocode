# Agent 数据库工具的读写边界：dev 可写（需确认）+ prod 只读

平台 Agent 新增数据验证能力（db_query / db_write）时，我们把写入面钉死在 dev 库、prod 库一律只读：db_write 的 schema 里根本没有 env 参数，prod 保护不依赖模型自觉；db_write 每次执行走既有确认卡。被否决的备选：全只读（灌不了测试数据，验证闭环残缺）与两环境都可写（模型自动改生产数据风险不可控）。

## 后果

- 「灌测试数据」= Agent 直接写 SQL 对 dev 执行，而不是写种子文件触发「重建 dev 库」——后者是 DROP 全库，会连带清掉用户手工数据，绝不开放给 Agent。
- 验证是**按需**的：工具挂载给模型，用不用由对话意图决定；不在生成流程里自动跑收尾验证（曾考虑「生成后自动闭环」，因每轮多耗时间与 token 被否）。
