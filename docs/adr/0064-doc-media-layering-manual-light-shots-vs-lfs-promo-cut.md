# 0064 文档媒体资产分层：手册浅色静态图进普通 blob，宣传短片走 git-lfs

- 状态：Accepted
- 日期：2026-11-20
- 关联：ADR-0055（控制台主题统一）、ADR-0058（登录页固定深色豁免换肤）、
  ADR-0062（控制台四页统一）、CONTEXT「操作手册」「宣传短片」「本机补美」

## 背景

手册 `docs/user-manual.md` 20 章只有 12 张配图，其中 8 个章节零图（第 2、6.1–6.3、7、8、9、
11、16、18 章），另有 4 张是 11-03 那代、早于 11-19~11-20 的两轮界面重构，与手册第 9 行
「已逐张对照当前代码核对」的声明不符。补图只能从演示站 `159.75.185.70:8100` 取：线上 CSS
里已含 `.zc-panel`（`7f20a6c`，2026-11-20 15:20 引入），它是唯一「代码 = master、数据 = 真实」
的界面来源，本机空库拍不出有内容的应用页与商店页。

同时要为平台做一条对外介绍视频。仓库当时 `.git` 只有 17M，`.gitattributes` 把 `*.png` 等
钉成 `binary` 但**没有配任何 LFS 跟踪规则**，而一条 1080p 成片的体积比整个仓库历史还大——
二进制一旦进 git 历史就永久占位，删不掉。

## 决策

1. **手册补图口径定为「广度 + 表现力」**：零配图章节全部补图，关键章节用**交互态分步图**
   （弹框已打开、☰ 菜单已展开、查询已出结果），同时重拍 4 张 11-03 旧代图，README 引用的
   那 8 张一并同步。第 19 章 FAQ 与第 20 章端口约定**刻意不配图**——纯文字更合适。
2. **演示站操作边界收在「只读 + 可逆预览」**：允许导航、展开已有内容、启停应用 dev 预览栈
   （停了即归零）；**禁止**发布、回滚、删除与写库。因此凡是需要真跑一次才存在的界面，
   不在演示站上拍。
3. **媒体主题分层，不做全局换肤**：手册配图一律浅色（与读者默认看到的界面一致），
   暗色只用于宣传短片。手册不因片子而重拍成深色。
4. **成片进仓，且只有视频进 git-lfs**：`docs/media/` 存放，`.gitattributes` 给 `*.mp4` /
   `*.webm` 加 `filter=lfs`；截图继续走普通 git blob（`*.png` 已钉 `binary`，单张 <1MB，
   进 LFS 只会让 clone 多一层依赖）。README 与手册顶部嵌播该视频。
5. **生成镜头优先在演示站上找零写入的等价态，实在没有才动用「本机补美」**：宣传片主体镜头
   来自演示站已有历史会话（真实数据、只读）；打字机镜头用「在输入框敲字但不点发送」拿到，
   发布进度弹框拍它的**受理前态**（底部才是「立即发布」，受理链只在 `autoStart && mode==='rollback'`
   才自动触发）。**执行记录（2026-11-20）：本机补美一次都没用上**——原先为它准备的本机 dev 栈
   与模型凭据没用出去，少维护一套环境。

## 备选方案

- **成片只留本地、不进仓**：零历史负担，也不依赖 LFS；但物料与手册分家，clone 的人拿不到，
  README 只能挂外链。被否（用户要进仓）。
- **压到 720p / 5MB 以内直接提交，不配 LFS**：省去 LFS 基建；代价是字幕与小字控件糊掉，
  而且那块二进制仍然永久留在历史里——省的是配额，不是不可逆性。被否。
- **手册整体改深色以求与片子同调**：两套物料完全一致、观感最统一；代价是既有 12 张浅色图
  全部重拍，镜头总量从约 20 涨到约 32，且深色截图嵌在浅色 GitHub/Gitee 页面上边缘突兀。被否。
- **为拿最真实界面在演示站上真点一次发布**：界面无可争议；但那台机 3.5G 内存，构建期间
  全站变慢，库里会多一条真实发布记录，失败还会卡住该应用的发布闸门。被否。

## 后果

- 视频进 LFS 后，**没装 git-lfs 的克隆拿不到成片内容**（只有指针文件）；出包与部署脚本
  不应把 `docs/media/` 当运行期资源依赖。
- 主仓在 Gitee（LFS 存储与流量有配额，推前先确认额度），GitHub 侧是每 15 分钟单向拉取的
  镜像——**镜像动作是否搬运 LFS 对象尚未验证**，若不带则 GitHub 上的视频链接会是死指针。
- 不可逆点在历史里：一旦带 LFS 对象推上去，把成片从 git 历史取出需要 rewrite + 强推两个
  remote，因此本决策实质上是「以后所有媒体资产默认按类型分流」的起点，而不只是这一条片子。
- 手册配图与视频是**同一次演示站行程的两个产物**：截图阶段若改了演示站主题或启停了预览栈，
  必须复位后再拍下一张，否则浅色口径会被自己拍脏；登录态是同账号单会话，脚本登录会把
  浏览器上的 `tsadmin` 顶下线，两边不能并行。
