# 0026 聊天页加「打开生产」，正式地址随应用行一起回表

聊天页操作条在「打开预览」右侧再加一个图标按钮**打开生产**：`window.open` 打开 `prod_url`，
`status_prod` 非 `running` 时禁用置灰给 tooltip，与「打开预览」同款口径。地址不新增一次点击时的
`GET /apps/{id}/urls` 往返，而是由 `app_service._with_public_urls` 在列表与详情里**顺带回 `prod_url`**。

「正式环境未启动就置灰」沿用 ADR-0021 对预览的那条判断，只是失败形态不同：prod 停着时网关路由表里没有
这个 slug，开出去是一片「应用不存在」的 404 提示页，比白屏更像「这个应用没了」——用户在这里刚发布完，
归因会更糟。所以也不代为启动正式。

地址走回表而不是点击时现取，是因为 `window.open` 落在 `await` 之后就出了用户手势窗口，会被弹窗拦截器
静默吞掉（`AppsView` 的「正式地址」只做复制，没有这个约束，才用的 hover 懒加载）。这不改变地址口径的
唯一事实来源仍是 `nics.app_url`（ADR-0016）：回表只是把那一份投影带进行里，前端不拼、后端不另立第二套。

## 后果

- ADR-0021 里「主区只剩一个带文字按钮加两个图标」的宽度结论作废，现在是**三个图标**
  （打开预览、打开生产、更多）。这一行的宽度余量本来就紧，再加第四个入口前应先考虑收进「更多」。
- `GET /api/apps` 与 `GET /api/apps/{id}` 每行多一个 `prod_url` 字段。它跟着 `ZEROCODE_SSL_ENABLE`
  与 `ZEROCODE_PREVIEW_HOST` 两个 env 变，是**实时投影**，不是发布时落库的快照——别拿它当历史地址存档。
- 聊天页的 5s 轮询（`useDevStatus`）顺带读出 `status_prod` 与 `prod_url`，不另起第二条轮询、
  也不订阅 deploy WS（ADR-0020 的后果条不变）。这个 composable 的名字从此只覆盖了一半职责，
  改名成本高于收益，靠注释说明。
- prod 侧仍没有运行日志接口，所以「更多」菜单里的「预览日志」不加 prod 对应项；要观测正式环境只有
  资源监控与发布记录。
