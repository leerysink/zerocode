# 先做登录体系，后做技能市场；技能为账户级、存放于用户库

用户提出"从网上安装 skills 到项目里"的需求。拷问后确定：技能消费者是平台 Agent
（Anthropic Agent Skills 标准，SKILL.md + frontmatter，GitHub/URL 安装），归属粒度是
**用户账户**而非单个工作区。由于"一切归用户"依赖身份体系，决定拆成两个项目按序交付：
先完成登录/用户隔离改造，再做技能安装功能。

技能生效方式：母本存平台数据区 `users/<uid>/skills/`，不拷入工作区目录；构建 system
prompt 时注入已启用技能的 name+description 清单，Agent 判断相关时再 read_file 读全文
（渐进披露，同 Claude Code）。启用粒度为用户级总开关。v1 仅消费技能的指令性内容，
Agent 无 shell 工具，技能内脚本不被执行。

## 后果

- 用户最初的直觉"装到项目目录"被显式否决：工作区目录不出现技能文件，
  避免技能被误当作应用代码打包/展示。
- Agent 需要获得读取用户技能库路径的受控读面（绝对路径白名单），是登录项目
  完成后的第一个下游改动。
