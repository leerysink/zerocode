# 0057 商店在线试用：复用作者 dev 预览栈，不起沙箱

- 状态：Accepted
- 日期：2026-11-19
- 关联：ADR-0026（未启动置灰、不代为启动）、M3-a 规格
  （`docs/superpowers/specs/2026-09-22-zerocode-app-store-design.md`）、
  CONTEXT「商店预览」「打开预览」「参考数据与演示数据」

## 背景

商店现状是盲装：装之前无法判断应用值不值得装，而一次安装就是全套重型流水线
（`app/store/install.py`：铺源码 + 建 dev/prod 分库 + 基线重放 + 构建镜像 + 起 prod 栈体检），
装错还没有卸载出口。需要在安装之前提供「看得到、摸得着」的预览，同时不暴露作者的真实生产数据。

## 决策

1. **商店预览 = 截图展示 + 在线试用两层**。截图选填（上限 5 张），无图条目用占位封面，
   不抬高上架门槛、存量条目零迁移。
2. **在线试用复用作者的 dev 预览栈（测试环境）**，不碰作者 prod 真实数据。试用数据写进
   作者 dev 库——按数据轨口径 dev 库本就是演示/测试数据范畴，数据边界问题由环境本身化解，
   不需要作者开关或只读拦截。
3. **闸门 = 源应用 `status_dev === running`（运行时检查）**：在跑才亮试用入口，停了置灰、
   **不代为启动**（同 ADR-0026 哲学）；不上架强制闸门，prod 永不承担试用。
4. **地址复用既有 `preview_url` 投影**（与「打开预览」同源），不新开通道、不走网关域名。

## 备选方案

- **平台沙箱演示实例**（每条目一套隔离 demo 栈、定期重置）：体验最好、试用不污染作者数据；
  但每条目一套容器，资源与运维成本比复用 dev 高一个量级。被否。
- **跳源应用 prod 试用**：复用发布/网关底座、成本中等；但试用数据写进作者真实 prod 库，
  无条件暴露给所有浏览者。拷问中先选此档，用户以「应该是启动测试环境」推翻，改取 dev。
- **按试用者按需起临时栈**：隔离最彻底；但起栈分钟级等待、并发试用时容器数爆炸。被否。
- **只读试用**（平台拦截写请求）：应用自己的 API 语义平台无法通用识别（登录也是 POST），
  技术上几乎不可行。被否。

## 后果

- **可试性绑定作者开发节奏**：dev 停时条目不可试（只看截图），这是明确接受的取舍；
  商店条目的试用面会随作者启停波动。
- **试用者与作者共用同一 dev 环境**：试用写入可能干扰作者正在进行的调试；干扰面限于
  测试环境（演示数据），不涉真实业务数据。试用前告知文案由 spec 定。
- **不可逆来源**：试用入口、闸门、地址投影全按 dev 接线；将来若改沙箱形态等于重做这条链。
- **Vite allowedHosts 坑天然绕开**：dev 栈 Vite 对网关域名回 403（2026-10-28 实测），
  但 `preview_url` 是直连地址（裸 IP/localhost 无条件放行）。若将来试用改走网关域名，
  必须先解决 allowedHosts，否则会复现「连得到但应用不答应」的第二层断点。
