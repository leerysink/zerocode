# 小程序作为移动栈应用的第三分发目标

平台已有 H5 与 APK 两个移动分发出口，用户还想把同一个应用发到微信小程序。决定让小程序成为**同一移动栈应用的第三个分发目标**：共用 `frontend/mobile/` 的 uni-app 源码，新增 mp-weixin 编译目标，上传到该应用绑定的小程序账号，接口仍走本应用后端。不新增 stack key、不新增发布端口、不拆应用。

## 备选方案

- **独立「小程序栈」应用**：小程序作为单独应用形态。被否决——平台今天没有跨应用调用通路（每个应用独享库与角色，后端与管理端都没配 CORS），拆两个应用等于先造一整套应用间地址绑定与数据通路。
- **web-view 壳小程序**：一个页面嵌 H5。被否决——需要业务域名校验文件；个人主体小程序不支持 web-view；H5 里的登录态与同源 `/api` 带不进小程序。
- **只导出源码给用户**：平台不构建、不碰密钥。它可以是外部条件不满足时的兜底，但不是平台能力；自动上传与预览码都无从谈起。

## 后果

- 小程序接口必须走**已备案的 HTTPS 合法域名**。一期复用平台统一网关域名 `https://{slug}.{GATEWAY_DOMAIN}`，每个应用的子域由用户在自己的小程序后台加入 request 白名单；证书必须是公共 CA（acme.sh / Let's Encrypt），自签不可用。
- 小程序是**真编译产物**，不是 APK 那种壳：业务代码编进包，每次改动都要重新上传、重新提审；APK「H5 更新不用重出包」的体验不适用于它。
- 只有移动栈应用有 uni-app 源码，非移动栈应用不提供该入口；存量非移动栈应用不做网页转小程序。
- 微信原生能力（登录、支付、订阅消息、分享回调）不在本期；静默微信登录已对齐为下一期。
