# 0005 应用资源监控用后端轮询 docker stats，磁盘低频独立采集

要展示每个应用消耗了多少 CPU、内存、硬盘（含实时与历史）。我们决定：由平台后端定时任务轮询 `docker stats --no-stream`（约 30s 一个点）采集 prod 栈容器的 CPU/内存，磁盘（数据库占用 + 工作区 du）走低频独立采集（约 5~10 分钟），两者都以单粒度滚动窗口存入平台库，保留天数可配置（如 `ZEROCODE_METRICS_RETENTION_DAYS`，默认 30）。前端按应用级汇总展示，仅覆盖 prod 栈。

被否决的方案：引入 cAdvisor + Prometheus + Grafana 全家桶（精度与历史能力最强，但新增三件基础设施、运维重，对单机 Docker Desktop、应用数量级不大的平台过重）；docker stats 流式长连接 + 窗口聚合（CPU 尖峰不丢，但要跟随容器重启、栈增删做连接管理，复杂度高）。选择轮询是因为它零新基础设施，且与现有部署栈一致——`app/deploy/` 已通过 docker CLI subprocess 编排 compose，采集复用同一条路径即可。

## 后果

- 轮询间隔内的瞬时 CPU 尖峰会采样平均掉，不是精确峰值——可接受，用户关心的是趋势与量级。
- 工作区磁盘按全量 du 统计（含 node_modules 等），低频采集正好消化其扫描成本。
- 保留窗口外的历史数据被淘汰，超过 N 天的趋势无法回溯；这是实现最简与回溯能力间的取舍。
- 平台库新增一张指标表属 SQL 变更，需按项目规范做版本化迁移记录。
