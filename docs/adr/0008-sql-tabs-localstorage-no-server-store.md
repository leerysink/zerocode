# 0008 查询页签持久化走 localStorage，不建服务端脚本库

用户要求 SQL 编辑器「支持保存」。我们决定：页签列表与 SQL 文本只写浏览器 localStorage，键按 `(appId, env)` 分区（形如 `zc.dbq.tabs.{appId}.{env}`），只存名称/顺序/活跃页签/文本，**不存执行结果**；写入遇配额异常则降级为「本次停止自动保存 + 黄条提醒」，不静默丢用户文本。服务端不新增表、不新增接口。

被否决的方案：
- 平台库新建脚本表（跨设备/跨人共享，纳入审计）——最"正规"，但要新增建表 SQL 版本文件、一套 CRUD 接口与归属校验，而当前诉求是"刷新别把我写的 SQL 弄丢"，不是"同事能看到我的查询"。
- 存成应用目录下 `.sql` 文件——与应用发布包、`sqlchange/` 迁移轨混在一起，市场打包与校验规则要连带改动，风险面最大。
- 只保持会话内多页签不丢内容（刷新即清）——没有回答"保存"这个诉求。

## 后果

- 换浏览器、换设备、清缓存都会丢页签；这是刻意接受的代价，未来若要做共享脚本库，是一条新增功能而非本次返工。
- 结果不进 localStorage 是硬约束：单条 SELECT 上限 5000 行，几页签的结果 JSON 足以击穿 5MB 配额。
- 页签按 env 隔离后，`watch(env)` 从「清空 SQL 文本」变为「切换到另一套页签」，原有的清空语义被替换。
