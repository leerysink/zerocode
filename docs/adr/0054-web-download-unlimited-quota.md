# 0054 web_download：任意公网资源落盘，业务配额不设闸

- 状态：Accepted
- 日期：2026-11-19
- 关联：ADR-0051（构建期摄入只收文本，当时否决 Agent 侧抓取工具）、ADR-0053（web_fetch 只读文本、
  SSRF 判定）、ADR-0052（子 run 只读白名单）、CONTEXT「联网能力」

## 背景

用户给 Agent 一个 git 仓库地址，要把里面的图片等资源贴进应用。现状两条通道都断：
仓库摄入（ADR-0051）只收 `TEXT_EXTS` 文本，图片被判 `not-text` 跳过；`web_fetch`（ADR-0053）
遇二进制只回「未读取正文」，不落盘。官网类应用引用仓库截图时只能摆「取不到原图」占位卡。

## 决策

1. **通道开在 Agent 工具面**：新工具 `web_download`，单 URL 逐次（`url` + `path`），不动摄入通道、
   不做子代理。ADR-0051 否决「Agent 侧抓取工具」的理由是出网面失控；ADR-0053 已用 SSRF 守卫把
   只读面开放，本票在同一守卫下补上落盘面——出网判定不新增，新增的只是字节落盘。
2. **输入任意公网直链，不限内容类型**（任意二进制）。主机范围沿 web_fetch：字面私网拒绝 +
   DNS 公网判定 + 逐跳重定向复检，复用同一套判定不另立名单。
3. **落点由模型给工作区相对路径**，越界/绝对路径拒绝（沿 write_file 守卫）；确认档 `CONFIRM_WRITE`，
   受现有 `agent.write_confirm` 开关控制，零新增配置。
4. **业务配额不设闸**（用户拍板）：不计入 `agent.web_max_fetches_per_run`，无单文件/总量上限。
   技术兜底保留：每请求超时（防慢滴响应挂死 run）+ 流式写盘（防大文件撑爆内存）。
   磁盘占用由使用者自己负责。
5. **不收录 `SUBRUN_TOOL_NAMES`**：下载是写动作，不属只读语义（沿 ADR-0052）。
6. **失败是带原因的正常结果，不抛 ToolError**（沿 web_fetch 约定）。

典型链路：`web_fetch` 读仓库页拿 links → `web_download` 逐个落盘（如
`frontend/public/images/chat.png`）→ `edit_file` 把占位卡改成本地引用。

## 备选方案

- **摄入通道扩容**（建应用时连图片一起烘快照）：改动最小，但已建应用享受不到、8MB 预算口径要变。被否。
- **独立子代理**：子 run 只读白名单语义不合，成本最高。被否。
- **仅图片 / 图片+字体白名单**：面小好管，但用户明确要任意二进制。被否。
- **共享 web 配额 / 独立配置键 / 沿 2MB 闸**：用户拍板不限制。被否。
- **恒确认 / 免确认**：前者批量下载点 N 次，后者与 write_file 口径不一致。取 `CONFIRM_WRITE`。
- **批量数组入参**：轮次省，但回执/确认/部分失败语义都要按批分叉。取单 URL 逐次，失败隔离清晰。

## 后果

- **外网字节可进工作区且无总量闸**：磁盘占用不设防，是用户明确接受的取舍；技术兜底只防挂死与
  OOM，不防磁盘满。
- **任意二进制含 svg / 可执行文件**：平台不执行它们，静态直出时浏览器按 Content-Type 处理；
  svg 内嵌脚本等渲染侧风险在规格里定对策。
- **与 ADR-0051 的关系**：摄入通道一行不动，两条通道语义独立——构建期文本快照 vs 对话期任意
  资源落盘。读起来像互相打脸的地方以本条为准。
