# 0009 打开工程目录默认走内置文件管理器，本机直开降为显式选择

「打开工程目录」原先默认 `auto`：本机（回环地址）访问调起系统资源管理器，远端或直开失败才降级到网页弹框。我们决定把默认改为 `web`——点它一律弹出内置文件管理器；`auto` 与 `system` 保留为设置页上的显式覆盖，后端 `/api/fs/open-folder` 端点不删。

理由：平台是面向多用户的 Web 控制台，“打开本地文件夹”依赖浏览器与后端同机这一前提，而这个前提在容器化、远端桌面、他人访问等场景下随时不成立；判错时用户看到的是“什么都没发生”。网页弹框不依赖任何环境假设，是能对所有人兑现的一致行为。把“能直开就直开”留在 `auto` 里，是给本机开发者的一次显式 opt-in，不再作为默认替所有人做主。

被否决的方案：代码里写死弹框并删除设置项（行为最一致，但彻底失去本机直开能力，容器等判不准环境的场合没有出口）；只改应用列表入口、聊天页右栏保持分流（两处对同一动作给出不同结果，用户心智断裂）。

## 后果

- 默认值有两处落点：前端 config store 的初始值 + changelog 播种的 `fs.open_folder_mode` 键。播种用 `ON CONFLICT DO NOTHING`，**已显式保存过 `auto` 的存量部署不会被刷成 `web`**——我们无法区分“用户主动选的 auto”与“保存设置时顺带写入的 auto”，宁可不动显式选择。这类部署要改行为得去设置页切一次。
- 应用列表与聊天页右栏两个入口共享同一判定，行为永远同步；未来若要分叉需另立决策。
- 菜单文案仍叫「打开工程目录」，不改名（“打开”对弹框同样成立），术语统一由 CONTEXT.md 承载。
