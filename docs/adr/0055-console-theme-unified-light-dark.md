# 0055 控制台主题：全局浅/深统一管辖，工作台独立主题退役

- 状态：Accepted
- 日期：2026-11-19
- 关联：CONTEXT「工作区工作台（workbench）」（旧裁定「工作台默认深色，可切浅色，控制台其余页面
  保持浅色不变」与「主题只落工作台根节点，不动全局 :root」由本 ADR 取代）、CONTEXT「控制台主题」

## 背景

控制台只有浅色一种主题；工作台（`WorkspaceFilesView`）有自己的浅/深开关
（`utils/theme.js`，键 `zc.workbench.theme.v1`，默认深色，`data-theme` + 局部 CSS 变量，
刻意不动全局 `:root`）。用户要求控制台增加「白天/黑夜」两种背景，即全局浅/深主题。
若保留工作台独立偏好，会出现两份偏好打架（控制台深色 + 工作台浅色）的割裂体验。

## 决策

1. **范围＝整个控制台**所有页面（含登录页与工作台）；**深度＝完整浅/深主题**——底色、文字、
   边框、antd 组件（darkAlgorithm）、Monaco 编辑器、监控曲线全适配，不是只换页面底色。
2. **统一管辖**：一份浏览器本地偏好（localStorage）是唯一真源，管辖全部控制台页面；
   工作台独立主题退役，「默认深色」作废，随全局默认。
3. **默认浅色**：没切过的用户升级后体验不变，想要深色自己切。
4. **手动开关**：规范入口在 AccountBar 顶栏「登出」旁；登录页不挂顶栏但主题仍生效。
   工作台状态栏旧按钮**保留为别名入口**——拨的是同一份偏好，不是第二份真源。
5. **旧偏好一次性继承**：旧键 `zc.workbench.theme.v1` 有显式值时作为全局偏好初值；
   监听 storage 事件跨标签页同步（工作台新标签里切主题，原标签跟随）。
6. **范围外**：生成的应用与预览 iframe 是应用自己的界面，不受控制台主题影响。

## 备选方案

- **只聊天页**：工作量小，但页面间跳转深浅混切割裂。被否。
- **各管各的**（工作台保留独立开关与默认深色）：改动最小，但两份偏好必然打架。被否。
- **全局默认 + 工作台可覆盖**：最灵活，但三层状态（全局/跟随/覆盖）复杂度最高。被否。
- **跟随系统 / 三态（跟随+手动）/ 按钟点自动**：用户拍板手动开关，与工作台既有交互同款。被否。
- **默认深色**：开发者工具惯例，但所有现有用户升级后界面骤变。被否。
- **只换底色**：深底浅组件对比崩坏，基本不可用。被否。

## 后果

- CONTEXT 工作台节两条旧裁定改写；工作台局部 CSS 变量机制可保留，但取值来源改为全局偏好。
- 工作台「默认深色」的肌肉记忆改变：升级后未显式切过的用户工作台变浅色（旧键有显式深色值者经继承保持深色）。
- 完整主题适配是一次性大工作量（自定义 less/scoped 样式、antd 覆写、图表配色）；
  此后新增页面与样式必须同时考虑两种主题，浅色不再是唯一默认假设。
